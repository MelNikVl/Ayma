# AYMA — маркетплейс ИИ-стартапов

[![CI/CD](https://github.com/MelNikVl/Ayma/actions/workflows/ci-cd.yml/badge.svg)](https://github.com/MelNikVl/Ayma/actions/workflows/ci-cd.yml)

Open Source маркетплейс ИИ-стартапов из Казахстана и СНГ с функцией **предзаказа услуг**.

Фаундер выставляет проект (GitHub, демо, описание) и открывает предзаказ — например, «Годовая подписка за 5 000 ₸» или «Кастомная доработка за 50 000 ₸». Спонсор нажимает «Стать спонсором» и оформляет предзаказ. Юридически это **купля-продажа будущей услуги, а не инвестиции**: спонсор не получает долю.

## Возможности

- Каталог с поиском, фильтром по тегам, сортировкой (популярные / новые / по звёздам) и пагинацией
- Карточки в стиле маркетплейса: логотип, теги, GitHub-бейдж «⭐ 1.2k · обновлено 2 дня назад», цена, кнопка спонсорства
- Страница стартапа: Markdown-описание, live-данные GitHub (звёзды, форки, язык, последние коммиты), sticky-блок предзаказа с прогресс-баром, список спонсоров, нижняя панель на мобильных
- Вход через **Telegram Login Widget** (с проверкой HMAC-подписи), сессия — подписанный JWT в httpOnly-cookie
- Оформление предзаказа → уведомление фаундеру в Telegram → оплата по ссылке фаундера (Kaspi Pay, Stripe Link…) → фаундер подтверждает оплату в кабинете → спонсор появляется на странице
- Личный кабинет: мои стартапы, входящие предзаказы (оплачен / отменить), мои предзаказы
- Модерация для администраторов (одобрить / отклонить, уведомления в Telegram)
- Светлая тема по умолчанию + тёмная через CSS-переменные; mobile-first вёрстка
- Docker Compose: Postgres + миграции + сид + приложение одной командой; CI на GitHub Actions

## Стек

Next.js 14 (App Router, Server Actions) · TypeScript strict · Prisma 5 + PostgreSQL 15 · Tailwind CSS · zod · jose · Docker

## Быстрый старт (Docker)

```bash
cp .env.example .env
# минимум: задайте SESSION_SECRET (openssl rand -base64 48)
docker compose up -d --build
```

Откройте http://localhost:3000. Сервис `migrate` применит миграции и базовые теги. Наполнить каталог реальными проектами (финал HackAlem.ai + Hatuli): `docker compose run --rm migrate npx tsx prisma/import-catalog.ts`. Демо-карточки для разработки — `SEED_DEMO=true`.

## Запуск на Windows одной командой

Нужен Docker Desktop. В PowerShell из папки проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Скрипт создаст `.env` со случайным секретом и dev-входом, соберёт контейнеры и откроет http://localhost:3000.

## Локальная разработка

```bash
npm install
cp .env.example .env            # пропишите DATABASE_URL и SESSION_SECRET
docker compose up -d db         # или свой Postgres
npx prisma migrate deploy
npm run db:seed
npm run dev
```

Telegram-виджет не работает на `localhost`, поэтому для разработки включите `ENABLE_DEV_LOGIN="true"` — на странице `/login` появится вход без Telegram (в т.ч. с ролью администратора). В продакшене (`NODE_ENV=production`) dev-вход отключён принудительно.

## Настройка Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather) → получите токен.
2. `/setdomain` → укажите домен сайта (например, `aimarket.kz`). Для тестов подойдёт туннель (ngrok, cloudflared).
3. В `.env`: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` (без `@`), `APP_URL`.
4. Свой Telegram ID (узнать у [@userinfobot](https://t.me/userinfobot)) добавьте в `ADMIN_TELEGRAM_IDS` — при входе получите роль ADMIN.

Виджет запрашивает право писать пользователю (`request-access=write`), поэтому бот может присылать уведомления о предзаказах и модерации.

## Переменные окружения

| Переменная | Обязательна | Описание |
|---|---|---|
| `DATABASE_URL` | да | Строка подключения PostgreSQL |
| `SESSION_SECRET` | да | Секрет подписи сессий, ≥ 32 символов |
| `APP_URL` | да | Публичный URL без `/` в конце |
| `TELEGRAM_BOT_TOKEN` | для входа | Токен бота |
| `TELEGRAM_BOT_USERNAME` | для входа | Username бота без `@` |
| `ADMIN_TELEGRAM_IDS` | нет | ID администраторов через запятую |
| `GITHUB_TOKEN` | нет | Повышает лимит GitHub API с 60 до 5000 запросов/час |
| `AUTO_APPROVE` | нет | `true` — публикация без модерации |
| `ENABLE_DEV_LOGIN` | нет | `true` — вход без Telegram (только dev) |
| `CRON_SECRET` | нет | Защищает `/api/cron/github` |
| `SEED_DEMO` | нет | `true` — добавить демо-карточки (по умолчанию выключено) |

## Рейтинг AYMA

**Проект (0–100)** — пять частей, шкалы логарифмические (первые голоса/звёзды дают заметный прирост):

| Часть | Макс | Что учитывается |
|---|---|---|
| Сообщество | 30 | голоса пользователей (24) + просмотры (6) |
| Поддержка | 20 | сумма и число оплаченных предзаказов |
| Разработка | 25 | стадия продукта, коммиты, авторы, звёзды GitHub |
| Карточка | 15 | логотип, обложка, описание/README, дорожная карта, преимущества, цена/срок внедрения, вложения, демо, **оформление страницы** |
| Команда | 10 | проект подтверждён командой, 2+ участника, открыт к коллабам, есть API |

**Разработчик (0–100)**: проекты (50: лучший ×0.4 + остальные ×0.1), поддержка (20), коллаборации (15), профиль (15). Уровни: Новичок → Билдер (20) → Профи (40) → Эксперт (60) → Легенда (80).

Формулы — `src/lib/score.ts`. Пересчёт: автоматически после голосов, предзаказов, правок карточки, коллабораций; полностью — кнопкой в `/admin` или `GET /api/cron/scores` с `Authorization: Bearer $CRON_SECRET`.

Встраиваемый бейдж для README: `![AYMA](<APP_URL>/api/badge/<slug>)`.

## Коллаборации и API

- В карточке проекта: статус API (нет / в планах / бета / открытый), протоколы (REST, GraphQL, gRPC, WebSocket, SDK, Webhooks, MCP), ссылка на документацию — отображается бейджем в каталоге.
- «Открыт к коллаборациям» + что ищете. Предложить коллаборацию можно проекту или разработчику (`/collabs`, страница проекта, профиль `/u/<github-login>`), ответ — в кабинете.

## Оформление страницы проекта

Команда выбирает тему (6 пресетов), акцентный цвет, шрифт заголовков и макет (классика / широкий герой / минимал), загружает логотип и обложку. Произвольный CSS/HTML не поддерживается намеренно — так страницы остаются безопасными и быстрыми.

## Языки

Интерфейс на казахском, русском и английском: `src/i18n/dictionaries/{kk,ru,en}.ts`. Язык выбирается переключателем (cookie `ayma_locale`), по умолчанию — из `Accept-Language`. Русский словарь — эталон: TypeScript не даст собрать проект, если в переводе не хватает ключа. Контент карточек хранится как его написала команда.

## Владение проектами и личный кабинет

- Вход для разработчиков — **через GitHub** (OAuth App), спонсоры могут входить и через Telegram. Аккаунты можно связать: войдите одним способом и нажмите «Привязать GitHub» в кабинете.
- У каждого проекта может быть **до 3 участников** (`StartupMember`). Первый — владелец.
- Импортированные проекты HackAlem никому не принадлежат, пока их не заберут. На странице проекта кнопка **«Это мой проект»**:
  - если GitHub-логин пользователя есть среди контрибьюторов репозитория — он сразу добавляется в команду;
  - иначе создаётся заявка (`ClaimRequest`), её подтверждает команда проекта в кабинете или администратор в `/admin`.
- Участники команды редактируют карточку: логотип (загрузка файла), цену и описание предзаказа, тексты, теги; видят входящие предзаказы и заявки.

### Настройка входа через GitHub

1. github.com → Settings → Developer settings → OAuth Apps → **New OAuth App**.
2. Homepage URL — `APP_URL`, Authorization callback URL — `<APP_URL>/api/auth/github/callback`.
3. Client ID и сгенерированный Client secret — в `.env`: `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`. Свой логин — в `ADMIN_GITHUB_LOGINS`.
4. Желательно задать `GITHUB_TOKEN` (personal access token без прав) — для проверки авторства и звёзд нужен лимит API выше 60 запросов в час.

## CI/CD

`.github/workflows/ci-cd.yml`:

1. **check** (каждый push и PR) — `lint`, `typecheck`, миграции и сид на Postgres, `next build`.
2. **image** (push в `main`) — Docker-образ → `ghcr.io/melnikvl/ayma:latest` и `:<sha>`.
3. **deploy** (если задана переменная репозитория `DEPLOY_HOST`) — по SSH: `git pull` + `docker compose ... pull && up -d`.

Для деплоя на свой VPS: Settings → Secrets and variables → Actions → Variables `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_PATH`; Secret `DEPLOY_SSH_KEY`. На сервере: клон репо, `.env`, `docker login ghcr.io` (если пакет приватный).

## Обновление данных GitHub

Звёзды и дата последнего коммита сохраняются в БД при создании/редактировании и по кнопке «Обновить GitHub» в кабинете. Для регулярного обновления повесьте cron:

```bash
# каждые 6 часов
0 */6 * * * curl -fsS -H "Authorization: Bearer $CRON_SECRET" https://your-domain/api/cron/github
```

## Как устроены деньги

Платформа **не принимает платежи** и не является стороной сделки — это снимает необходимость лицензии платёжной организации. Фаундер указывает свою ссылку на оплату; спонсор платит напрямую; фаундер подтверждает оплату в кабинете. Шаблон условий — на странице `/terms`, адаптируйте его с юристом.

Хотите встроенный эквайринг? Добавьте провайдера в `src/app/actions/preorder.ts` (создание счёта) и webhook-роут, который переводит `PreOrder.status` в `PAID`.

## Разделы сайта

Три основных раздела в шапке, у каждого своя строка подразделов:

| Раздел | Подразделы |
|---|---|
| **Проекты** | каталог `/`, рейтинг проектов `/rating`, добавить проект |
| **Команды** | все команды `/teams` (участники на AYMA + авторы кода из атласа, фильтры «На AYMA» и «Открыты к коллабам»), разработчики `/rating?tab=devs`, коллабы `/collabs` |
| **Заказчики** | для компаний `/business`, заказы `/jobs`, разместить задачу `/jobs/new` |

## Биржа задач: разработчики и компании

Раздел «Заказчики»: `/business` — лендинг для компаний (как это работает, идеи задач, свежие заказы, готовые решения), `/jobs` — лента заказов для разработчиков.

Поток: компания входит (Telegram или GitHub) → `/jobs/new` описывает задачу (категории, бюджет, срок, контакт) → разработчики откликаются с ценой и сроком, можно от имени своего проекта → заказчик выбирает исполнителя → **контакты открываются обеим сторонам** (контакт заказчика до выбора скрыт) → задачу можно отметить выполненной, это добавляет исполнителю баллы в рейтинг разработчика.

Уведомления об откликах и выборе исполнителя приходят в Telegram (если пользователь входил через него). Ограничения от спама: до 5 открытых задач на заказчика, до 30 откликов в сутки на разработчика. Модерация — админ может скрыть задачу. AYMA не берёт комиссию: оплату стороны обсуждают напрямую.

## Инвестиции в проекты

У каждого проекта — кнопка **«Инвестировать»** (в каталоге, на карточке, на странице проекта и в мобильной нижней панели).

- Команда указывает желаемую сумму в карточке → вкладка «Бизнес» («Ищет инвестиции» + описание). Тогда в каталоге видно «Ищет 50 млн ₸», а на странице проекта — прогресс «Заявлено инвесторами».
- Если сумма не указана — «Проект пока не ищет инвестиции», но инвестор всё равно может «Сообщить об интересе».
- Инвестор на `/startup/<slug>/invest` оставляет **заявку о намерении**: сумма, формат (доля, SAFE, заём, грант, обсудим), контакт, сообщение. Команда получает уведомление в Telegram и видит заявку в кабинете (раздел «Инвесторы»: «В переговоры» / «Отклонить»).
- AYMA деньги не принимает и сделку не оформляет — это сбор намерений; так не нужна лицензия брокера/краудфандинговой площадки. Дисклеймер выводится рядом с кнопкой.
- Предзаказ услуг остался вторичным блоком на странице проекта.

## Резюме и LinkedIn разработчика

В личном кабинете → «Профиль разработчика» можно указать ссылку на LinkedIn и загрузить резюме в PDF (до 5 МБ, проверяется сигнатура файла). Ссылки показываются в блоке «Команда на AYMA» на странице проекта, в профиле `/u/<login>` и в откликах на бирже задач. Заполненные LinkedIn и резюме добавляют баллы в часть «Профиль» рейтинга разработчика.

## Спонсорство в USDT (MetaMask)

Команда указывает EVM-кошелёк (0x…) в карточке проекта → вкладка «Бизнес». На странице проекта появляется блок «Поддержать в USDT»:

- сети: **Polygon** (USDT0), **BNB Smart Chain** и **Base** — адреса контрактов в `src/lib/crypto.ts`;
- спонсор подключает MetaMask, сайт сам переключает/добавляет сеть и отправляет `transfer` USDT **напрямую на кошелёк команды** — AYMA средства не хранит и ключей не видит;
- сервер (`src/lib/crypto-verify.ts`) проверяет квитанцию транзакции через публичные RPC: успешна, перевод именно USDT-контракта, получатель — кошелёк команды. В базу (`CryptoDonation`) попадают только подтверждённые переводы;
- подтверждённые суммы видны в списке спонсоров со ссылкой на обозреватель и учитываются в части «Поддержка» рейтинга (по курсу 500 ₸ за USDT).

Где включить: участник команды открывает свой проект → «Добавить кошелёк» (или «Редактировать» → вкладка «Бизнес») → вставляет адрес из MetaMask → сохраняет. Пока кошелька нет, посетители блок не видят.

Перед включением в проде проверьте юридическую сторону приёма криптовалюты в вашей юрисдикции.

## Структура

```
prisma/
  schema.prisma          схема БД
  migrations/            SQL-миграции
  seed.ts                теги + демо-данные
src/
  app/
    page.tsx             каталог
    startup/new          создание стартапа
    startup/[slug]       страница стартапа (+ /edit, /sponsor)
    dashboard            личный кабинет
    admin                модерация
    login, terms
    actions/             server actions (стартапы, предзаказы, модерация)
    api/auth/*           Telegram-callback, logout, dev-вход
    api/cron/github      обновление звёзд
    api/health           healthcheck
  components/            UI-компоненты
  lib/                   prisma, сессии, Telegram, GitHub, валидация, форматирование
```

## Отличия от исходной схемы

В модель `Startup` добавлено поле `paymentUrl` (ссылка фаундера на оплату) — она копируется в `PreOrder.paymentLink` при оформлении. Добавлены индексы на `PreOrder` и каскадное удаление предзаказов вместе со стартапом.
